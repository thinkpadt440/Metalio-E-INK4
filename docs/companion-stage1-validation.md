# Companion 第一阶段实现与验证

日期：2026-11-24。分支：feature/companion；起点6729fdb。阶段0基线的ESP-IDF构建和UI预览已通过，工作区起始干净。

## 已实现

- components/esp-ml307/include/web_socket.h、src/web_socket.cc：分片/消息状态改为连接实例持有；单帧默认2048字节保持不变；新增独立完整消息上限，旧客户端默认65535字节，避免无限重组，同时保留多帧组成较长旧消息的能力。
- 改为有界缓冲增量处理TCP拆包/合包；无符号解析扩展长度；在等待/分配负载前检查帧和累计消息大小。拒绝无起始帧的continuation、分片期间新数据帧、异常控制帧、未协商RSV/服务端掩码等输入。
- 连接前安装回调，握手响应可带首条消息；失败、Close、断线/重连时清理接收状态。收到Ping回复同负载Pong；新增OnPong供后续心跳计时使用。连接状态使用原子变量，接收/Close使用同一递归互斥锁。
- main/harness/transport.h/.cc：独立工厂分别设置Harness单帧与完整消息8192字节；新增完整JSON对象解析，按实际长度读取，拒绝超限、嵌入NUL和尾随非空白。这里只创建/配置对象，不建立真实Harness连接。
- main/protocols/websocket_protocol.cc：原聊天JSON接收改为带长度解析，错误日志不再对非NUL结尾缓冲使用%s。
- Dashboard只迁入已确认的Newlib nano数字兼容修复，不迁入演示数据、模型名或审批脚本。UI预览补充零值、千分位边界与32位最大计数验证。

协议字段、端点与时序未变。两份接口文档只补充固件配置API说明。

## 验证

1. WebSocket主机测试：36个场景通过，启用AddressSanitizer和UndefinedBehaviorSanitizer。测试直接编译真实WebSocket和Harness transport源码，cJSON来自ESP-IDF。
2. 关键覆盖：2KB旧帧、8KB JSON、完整重组超限、双连接交错、中文字符跨帧、任意TCP边界、6000帧合包、200条随机分块消息、25次错误后重连、Ping/Pong/Close、无NUL结尾JSON和异常报文。
3. 实际页面离线检查：Dashboard数字、Session/配置、分页、BOOT录音控制器、PCM边界和60次页面导航。
4. ESP-IDF v5.5.4 / ESP32-S3最终构建通过；应用0x3534d0字节，最小应用分区0x500000字节，剩余33%。构建中仍有原有文件的未使用变量/函数与volatile告警，本阶段未改动那些文件。
5. git diff --check。板级/音频/显示/TCP与TLS驱动、分区表、sdkconfig均未修改。

旧代码在新增测试的首轮运行中有14项失败；修复后所有36项通过。测试替身不验证真实RTOS时序与10秒等待，不能代替真机与后端联调。

## 使用约束与待验证

- 回调在接收任务执行，不直接操作LVGL、销毁连接或调用Connect；交由拥有连接的应用任务处理。接收错误会令逻辑连接失效并通知OnError，应用任务需销毁/重建底层连接，不在TLS接收回调中等待自身退出。
- 单帧默认值保持2KB，旧消息完整重组上限是新增的65535字节；若旧服务确有超过此上限的消息，需在独立连接上明确配置并验证，不能默默取消内存边界。
- 当前未验证真实Wi-Fi/TLS/4G端到端、设备线程并发压力、运行时栈与内存峰值、待机联网；需要真实服务与设备时逐项补验。
- 目前没有后台连接、HTTP状态同步、事件消费、录音上传或业务状态机。阶段2继续实现HTTP/WS客户端、hello/sync/ready、超时和退避重连。
- 本阶段未刷机、未提交、未推送。演示分支不变。
