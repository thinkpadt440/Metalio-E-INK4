# Metalio E-Ink4 当前固件状态与真机调试

记录当前 feature/companion 固件状态，方便构建、烧录和设备端验收；不替代 Harness 接口约定。

- 固件版本：0.1.1-dashboard，源码基于无名科技官方 2.0.63，ESP-IDF v5.5.4。
- 目标设备：Metalio E-Ink4，3.97 英寸 E-Ink、ESP32-S3、16MB Flash。
- 显示：面板原生 800×480；UI 逻辑坐标为 480×800 竖屏。

## 当前已实现

- Dashboard 显示六项统计。切换全部、30天或7天会发起请求，停留期间约每 15 秒刷新。各周期单独保留最近成功结果，空值显示 --。
- 助手显示服务端最近会话并支持分页。进入会话时读取当前设置，模型和授权选项来自服务端目录。更新时用配置版本校验，冲突时刷新设置并提示重新选择。
- 首页或会话列表长按 BOOT 时创建或复用该设备的固定闲聊。会话确认后若 BOOT 仍按住，开始本地录音。松开后停止。在指定会话页长按则使用当前会话。
- 录音复用 AudioService，采集 16kHz、16bit、单声道 PCM，最长 30 秒，缓冲放在 PSRAM。录音结束后自动分块上传，收到匹配的 accepted 和 run_id 后释放缓冲。转写通过 asr.final 回显。
- 进入会话后显示最新一屏。音量 + / − 或盖板键翻阅上下页，翻到当前批次最前才请求更早的历史。查看旧页时，点“有新消息”回到最新。
- 聊天页上方显示任务状态和进度。点击“取消任务”并确认后，先等待服务端停止，再显示“任务已取消”。已完成的操作继续有效。重复或较旧的状态不会覆盖终态。
- 设备把最多 12 条未结任务的会话 ID 和任务 ID 保存在 NVS。重连或重启后先同步活动快照，再查询快照中缺失的已追踪任务。后端地址和设备 ID 需要与记录一致。
- 当前会话收到审批时打开详情页。其他会话收到审批时，点击待审批提醒可查看。审批正文默认只显示描述。要允许时，点击「查看操作」，再用音量键或盖板键逐页核对完整操作。详情超出设备可读范围时，前往 Harness 网页核对，设备仍可拒绝。
- 助手标题显示真实连接状态。固件配置服务地址后，Dashboard 和助手在使用期间保持联网。默认浅睡关网，唤醒后重连同步。演示固件支持编译时开启在线待机。

## 构建与烧录

在 WSL Ubuntu 22.04 中：

~~~bash
cd /home/sven/proj/eink4
. /home/sven/esp/esp-idf/export.sh
idf.py build
~~~

设备已经刷过兼容的本项目分区和资源镜像时，可只刷应用：

~~~bash
idf.py -p /dev/ttyACM0 app-flash monitor
~~~

首次刷机，或分区表、字体/资源镜像与本地构建不一致时，完整烧录。更新新版内置关机图也需要刷入 resources 分区：

~~~bash
idf.py -p /dev/ttyACM0 flash monitor
~~~

build/Metalio-E-Ink4.bin 是应用镜像，不能当完整镜像写入 0x0。完整合并镜像在 build/firmware/，使用前核对生成的烧录地址。设备端口因 USB/WSL 附加状态变化时，以 ls /dev/ttyACM* 的实际结果为准。

经典睡眠页和自定义壁纸睡眠页都显示 Lenovo 标识。关机时优先使用设备设置中选定的有效 SD 卡壁纸，否则显示 resources 分区的内置关机图。

## 配置待机模式

在设备的「设置 → 助手」填写 HTTP(S) 服务地址并点「保存并重启」。地址填到主机和端口，例如 http://192.168.1.10:8780；WebSocket 路径由固件自动生成。保存的地址在断电和只刷应用后仍有效。清空后保存会停用连接；设备首次未保存过地址时使用编译默认值。有正在采集或未确认的录音时，先在助手里处理录音再切换服务器。

运行 idf.py menuconfig 并进入 Harness Companion 可指定出厂默认地址、设备 ID 和待机选项。参见 [阶段2记录](companion-stage2-validation.md) 和 [模拟后端使用说明](../tools/mock_backend/README.md)。

| Keep Harness online on the standby screen | 设备行为 |
| --- | --- |
| 关闭（默认） | 短按 POWER 或达到无操作时限后进入原有浅睡。设备暂停接收事件，唤醒后重新同步活动任务、审批和当前会话。 |
| 开启（演示） | 同样进入待机画面，CPU 和 Wi-Fi 保持工作。画面显示在线状态或“待审批 N”。点击提示进入助手，查看对应会话的审批。短按 POWER 回到待机前页面，长按 BOOT 打开助手。 |

在线待机比浅睡耗电。配置有效服务地址后在线待机才生效。POWER 长按关机、原有待机关机时限和低电量保护仍然生效。保存配置后重新构建。已有兼容分区及资源的设备可用 app-flash。

## 真机验收

1. 在 Windows 双击模拟后端的 start_mock_backend.bat。刷入当前固件后，在设备「设置 → 助手」填写它的局域网地址，保存并重启。详见 [模拟后端使用说明](../tools/mock_backend/README.md)。
2. 打开首页，切换全部、30天、7天。核对会话数分别为 53、18、5，消息数分别为 5,980、742、96。停止模拟后端，确认设备提示离线并保留该周期上次的数据。重启模拟后端后确认连接和数据恢复。
3. 进助手，选择“固件开发”。核对服务端返回的模型和授权值，修改一项，返回会话列表再进入，确认变更仍在。“项目规划”的设置独立保留。
4. 从首页或列表长按 BOOT，等“固定闲聊”出现并开始录音。说话超过 200 毫秒后松开，确认界面显示发送、录音已接受，然后出现示例转写文本和助手回复。快速松手时，等待中的会话请求可以完成，麦克风应保持停止。
5. 进入“项目规划”。用音量 + 查看旧页，到当前批次最早处继续按 +，确认新的一批从更早文本接上。再用音量 − 往新记录翻。
6. 停留在旧页，从 Windows PowerShell 执行下面的命令。设备应提示“有新消息”，当前页位置保持不动。点击提示确认能看到完整的新回复。在最新页再触发一次，检查回复逐段显示。

   ~~~powershell
   Invoke-RestMethod -Method Post -Uri 'http://127.0.0.1:8080/mock/stream'
   ~~~

7. 用默认浅睡配置，从 Dashboard 和助手页分别短按 POWER 进入待机。在电脑侧确认 WS 断开，在待机期间发起第 10 步的审批。短按 POWER 唤醒，再进助手，确认获取了同一条待审批、当前任务和最新历史。另测无操作自动待机及长按 BOOT 唤醒进入助手，查看串口有无异常重启。

8. 验证接受确认丢失。在 Windows 停止模拟后端，从其目录执行以下命令，再录一段音。服务只跳过首次 audio.end 确认，设备随后通过原录音 ID 重连查询结果。期间再次长按 BOOT 应保留原录音，最终应只看到一条转写和一条回复。

   ~~~powershell
   $env:HARNESS_MOCK_DROP_AUDIO = 'end_ack'
   python mock_backend.py
   ~~~

   结束验证后，关闭服务，执行 Remove-Item Env:HARNESS_MOCK_DROP_AUDIO，再按普通方式启动。

9. 打开“项目规划”，在 Windows PowerShell 发起一个约 9 秒的任务。观察进度，点击“取消任务”，再点击“确认取消”，确认状态依次显示等待停止和已取消。重新发起一个任务，运行中返回首页或断开设备 Wi-Fi，稍后重进会话核对任务结果。验证重启恢复时，保持模拟后端运行，在任务进行中重启设备。

   ~~~powershell
   Invoke-RestMethod -Method Post -Uri 'http://127.0.0.1:8080/mock/run'
   ~~~

   模拟后端重启会清除任务，因此这一步用设备关网或重启来验证恢复。

10. 打开“项目规划”，在 Windows PowerShell 触发审批。点击「查看操作」，读完详情后点击「仅本次允许」，确认返回原聊天位置并看到“审批已允许”。重新触发后试一次拒绝，确认任务没有继续执行。

    ~~~powershell
    Invoke-RestMethod -Method Post -Uri 'http://127.0.0.1:8080/mock/run?mode=approval'
    ~~~

    追加 mode=approval_long 可检查多页详情，mode=approval_web_only 可检查只能在网页批准的情况。测试其他会话的提醒时，保持当前聊天页，给测试 URL 添加 session_id=sess_firmware。真实 Harness 决策与墨水屏刷新仍需联调。其他模式见 [模拟后端使用说明](../tools/mock_backend/README.md)。

11. 用在线待机配置重复第 7 步。进入待机后，检查 WS 连接 ID 持续有效，再发起第 10 步的审批。设备无需唤醒即可显示“待审批 1”。点击提示进入助手并查看详情。另测手动和超时待机、短按 POWER 返回、长按 POWER 关机，以及断开 Wi-Fi 后恢复连接。用相同亮度和网络条件记录两种模式的待机电流与实际刷屏效果。

未确认的录音仅保存在 RAM。短于 200 毫秒的录音不上传；意外掉电会丢失尚未确认的本地录音。连接或确认超时后，最多自动尝试三次，之后可手动重试或明确放弃。设置冲突时重新读取会话设置，原录音保持原版本，页面提示放弃后重录。

主机测试覆盖 480×800 Dashboard 和助手页面、与模拟后端的 HTTP/WS 交互，以及用模拟电源状态验证的在线审批和睡醒同步。ESP32 实机的墨水屏待机、物理按键、功耗、USB 烧录及正式 Harness 后端的测试记录待补。设备保留最新和附近的历史批次，反向逐批回读保留最多 24 个游标。若游标过期，按页面提示回到最新重新加载。
